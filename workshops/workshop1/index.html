Repository Architecture

Recommended ML Repository Structure

A clean, industry-standard folder hierarchy for organizing code, notebooks, models, and data in your GitHub projects.

1. Standard Professional Folder Hierarchy

Rearrange flat starter template files into clean directory folders so your GitHub repository follows production engineering practices (Note: Not all folders are needed — use what applies to your specific project!): 

my-ml-project/
├── README.md               # Project overview, setup commands, & model summary
├── .gitignore              # Ignore rules for cache, raw data, and model binaries
├── requirements.txt        # Python package dependencies
├── data/                   # Dataset storage directory (never committed to git)
│   ├── raw/                # Unmodified raw source data
│   └── processed/          # Cleaned & imputed dataset files
├── notebooks/              # Jupyter notebooks for visual EDA & interactive demos
├── src/                    # Modular Python source code & pipeline scripts
│   ├── data/               # Ingestion, cleaning, & preprocessing modules
│   ├── models/             # Model training, evaluation, & prediction scripts
│   └── utils/              # Shared helper functions & utility scripts
├── models/                 # Saved model weights & serialized binaries (.pkl)
└── tests/                  # Unit tests & verification scripts

2. Core Folder Organization Guidelines

  • Keep Source Code in src/: Place pipeline scripts (e.g. data ingestion, model training, prediction interfaces) inside a dedicated source folder.
  • Isolate Notebooks in notebooks/: Keep exploratory Jupyter notebooks separated from production Python scripts so your root directory stays clean.
  • Isolate Data in data/ (Git-Ignored): Store local dataset files inside data/raw/ or data/processed/, and ensure the data/ folder is listed in .gitignore.
  • Store Serialized Models in models/: Save serialized model artifacts (like .pkl or .onnx files) in a models/ directory (also git-ignored).

3. Recommended Repo Enhancement Challenges

  • Challenge 1: Folder Migration: Create src/, notebooks/, and models/ folders in your repo and move flat starter files into their respective directories.
  • Challenge 2: Feature Engineering: Add a new feature calculation in your training script and test if classifier accuracy improves.
  • Challenge 3: Multi-Model Evaluation: Compare performance across Decision Trees, Random Forests, and Logistic Regression models.
